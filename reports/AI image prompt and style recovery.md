# Read the file first, then rebuild the style

Whether you can recover how an AI image was made depends almost entirely on one thing: **is the original file's embedded metadata still there?** Local Stable Diffusion front-ends (A1111/Forge, ComfyUI, InvokeAI, Fooocus, NovelAI) write the full recipe into the file as plain text: prompt, negative prompt, seed, sampler, model hash and, for ComfyUI, the whole node graph. Tools such as exiftool, SD Prompt Reader and ComfyUI's drag-and-drop read it back exactly. Commercial services (ChatGPT/gpt-image, Gemini/Nano Banana, Firefly) embed only provenance, meaning C2PA credentials, an IPTC "AI-generated" tag and an invisible watermark. **They never embed the prompt.** Almost every social upload, chat app, re-encode or screenshot strips the metadata entirely. Once it is gone, **the exact prompt, seed and settings cannot be recovered by any tool.** Research inverters and `/describe`-style tools get you a prompt with the same meaning, never the same words. The practical goal therefore shifts from "find the prompt" to "find the model family and write a prompt plus style reference that regenerates something close". A vision model writes the description, a multi-reference model (FLUX.2, USO, Krea 2, Midjourney `--sref`) carries the look, and a style LoRA locks it in when you need many consistent images. Claude fits this loop well as the orchestrator. It needs tools for two jobs it cannot do itself: reading metadata, which it never sees, and generating images. No single existing skill or MCP server covers the whole pipeline, so the best setup today is a small custom skill wired to exiftool, c2patool and a generation MCP server.

## Local generators leave the full recipe in the file; commercial ones leave only a signature

The differences between generators decide your first move. **A1111 and Forge** store their "infotext" (prompt, negative, seed, sampler, model hash) in a PNG `tEXt` chunk keyed `parameters`. In JPEG and WebP files the same text goes into EXIF `UserComment` ([A1111 commit](https://mirrors.sustech.edu.cn/git/github_fork/stable-diffusion-webui/-/commit/a112168d2814d691936a7fb1d4cde5acb8440679)). **ComfyUI** stores two JSON graphs, `prompt` (API format) and `workflow` (UI format). Dropping the PNG onto the canvas restores the entire pipeline, including model names, LoRAs and seeds ([ComfyUI docs](https://docs.comfy.org/development/api-development/workflow-metadata)). That richness has a downside: shared ComfyUI PNGs have leaked API keys stored in node inputs ([nhimg.org](https://nhimg.org/articles/comfyui-png-metadata-turns-image-sharing-into-secret-exposure/)). **NovelAI** writes regular text chunks and also a "stealth pnginfo" copy hidden in the alpha channel's least significant bits. It adds a `signed_hash` that verifies the image came from NovelAI's models ([NovelAI repo](https://github.com/NovelAI/novelai-image-metadata)). Fooocus has a native JSON scheme and an A1111-compatible one ([fooocus-metadata](https://pkg.go.dev/github.com/fkleon/fooocus-metadata/fooocus)).

Commercial services work differently. OpenAI says ChatGPT, Codex and API images carry **C2PA metadata plus a SynthID watermark** ([OpenAI help](https://help.openai.com/en/articles/8912793-c2pa-in-chatgpt)). Google's Nano Banana Pro images from the Gemini app and Vertex AI carry C2PA and SynthID too ([Google blog](https://blog.google/technology/ai/ai-image-verification-gemini-app/)). Google's own docs warn that C2PA does not guarantee its assertions are true ([Vertex AI docs](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/content-credentials)). The best you get from these files is "made by vendor X at time T, possibly edited", not the prompt. Midjourney is the murky case. It has committed to the IPTC Digital Source Type tag ([IPTC](https://iptc.org/news/midjourney-and-shutterstock-ai-sign-up-to-use-of-iptc-digital-source-type-for-generated-ai-content/)). One vendor guide claims Midjourney's Description field holds the prompt and its GUID holds the job ID ([Fast.io](https://fast.io/resources/ai-generated-image-metadata-detection-tools/)), but Midjourney does not document this and another writer says the fields vary ([bushe.co](https://bushe.co/answers/detect-midjourney-images-from-metadata/)). Check, but don't count on it.

The reading tools are mature and mostly free:

| Need | Tool | Status (Nov 2026) |
|---|---|---|
| Dump everything (PNG chunks, EXIF, XMP/IPTC, JUMBF) | [exiftool](https://github.com/exiftool/exiftool) | Active; the universal first pass |
| Normalized SD fields across A1111, ComfyUI, InvokeAI, NovelAI, Draw Things, SwarmUI, Fooocus-MRE | [SD Prompt Reader](https://github.com/receyuki/stable-diffusion-prompt-reader) (GUI + `sd-prompt-reader-cli`, TXT/JSON, batch) | ~1.3k★, active; reliable only on basic ComfyUI graphs |
| Python parsing library | [sd-parsers](https://github.com/d3x-at/sd-parsers) | Small, slowing |

| A1111/Forge recovery | Built-in PNG Info tab → "send to txt2img" | Works; both projects' pushes have slowed |
| NovelAI alpha-channel data and signature | `nai_meta.py`, `nai_sig.py` ([NovelAI repo](https://github.com/NovelAI/novelai-image-metadata)) | Official |
| C2PA validation | c2patool, c2pa-python, c2pa-rs ([contentauth](https://github.com/contentauth/c2pa-rs)) | Actively maintained by the CAI |

Civitai adds one more route. It identifies checkpoints and LoRAs by file hash, so a hash pulled from metadata can be looked up through its public API to name the exact model files ([Civitai article](https://civitai.com/articles/10564); [Civitai API](https://developer.civitai.com/docs/api/public-rest)). If the image came from a Civitai post, check the post's generation data before doing anything else. That is real recovery, not a guess.

## Metadata dies on upload; watermarks are the only signal that survives

Metadata breaks easily. Discord users reported an update that stripped all text metadata and broke SD prompt sharing ([Discord community](https://support.discord.com/hc/da/community/posts/13996617793559-Image-metadata-getting-removed)). Converters such as XnConvert drop SD metadata even with "keep metadata" enabled ([XnView forum](https://newsgroup.xnview.com/viewtopic.php?p=197464)). A Washington Post test of eight social platforms found **none preserved or displayed Content Credentials** ([IPTC](https://iptc.org/news/ai-disclosure-on-social-media-a-work-in-progress/)). From most to least durable: invisible watermarks (SynthID, the SDXL dwtDct mark), then NovelAI's alpha-LSB payload, which survives chunk stripping but not JPEG conversion or flattening, then C2PA/XMP/EXIF/text chunks, which are lost on almost any upload. A screenshot keeps only what the pixels carry.

Once metadata is gone, only two kinds of generator identification hold up. The first is **SynthID**: upload the image to Gemini and ask whether Google AI made it. This works only for Google's watermark, and Google advises cropping tight and avoiding collages ([Gemini support](https://support.google.com/gemini/answer/16722517)). SynthID survived at least one stripping tool in The Register's test ([The Register](https://www.theregister.com/2025/11/20/google_ai_image_detector/)). The second is **NovelAI's signature**, when its alpha data is intact. Generic "is it AI" detectors give probabilities, not answers. On art, Hive reached about 98% accuracy with no false positives, while Optic and Illuminarty did worse, and adversarial noise degraded Hive ([arXiv 2402.03214](https://arxiv.org/abs/2402.03214)). Outside art, Hive missed most AI-generated Western blots, and the study showed that **at low prevalence most positive flags are false** ([arXiv 2407.10308](https://arxiv.org/pdf/2407.10308)). No maintained open tool names the specific checkpoint (SDXL vs Flux vs Midjourney v7) from pixels alone. Model attribution remains research code, and watermarks can be attacked: UnMarker reported a 79% success rate against SynthID, which DeepMind disputed ([IEEE Spectrum](https://spectrum.ieee.org/ai-watermark-remover)). Anthropic itself states that **Claude cannot determine whether an image is AI-generated** ([Claude vision docs](https://platform.claude.com/docs/en/build-with-claude/vision)). Without metadata, naming the model family comes down to expert judgment from visual tells, confirmed by regenerating on the suspected model.

## Stripped images yield a prompt with the right meaning, never the original words

No tool recovers the exact prompt from pixels. Many different prompts produce near-identical images, and the seed and sampler noise leave nothing recoverable. Midjourney's own `/describe` docs say its four suggested prompts cannot recreate the image exactly ([Midjourney docs](https://docs.midjourney.com/docs/describe)). Kaggle's 2023 image-to-prompt competition is a useful reference point. Scoring by sentence-embedding similarity to the true prompt on SD 2 images, CLIP Interrogator scored about **0.41–0.46** and strong fine-tuned entries about 0.56 ([UBC wiki](https://wiki.ubc.ca/Stable_Diffusion:_Image_to_Prompts)). That means the same topic in different words. Research inverters do no better at exact text. PEZ ([NeurIPS 2023](https://papers.neurips.cc/paper_files/paper/2023/file/a00548031e4647b13042c97c922fadf1-Paper-Conference.pdf)), PH2P, which reaches 0.77 CLIP similarity ([CVPR 2024](https://openaccess.thecvf.com/content/CVPR2024/papers/Mahajan_Prompting_Hard_or_Hardly_Prompting_Prompt_Inversion_for_Text-to-Image_Diffusion_CVPR_2024_paper.pdf)), VGD ([ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/file/cd61329e2c14b93a89d617c914140f64-Paper-Conference.pdf)) and the CVPR 2026 diffusion-LLM inverter ([supplement](https://openaccess.thecvf.com/content/CVPR2026/supplemental/Devulapally_Interpretable_Prompts_made_CVPR_2026_supplemental.pdf)) all land in the same semantic neighbourhood. The most useful finding for practitioners comes from a systematic comparison: **a plain BLIP-2 caption often regenerated images closer to the original than discrete prompt optimisers did**, and CLIP image-text similarity turned out to be a poor proxy for regeneration quality ([Williams et al.](https://arxiv.org/abs/2408.06502v2)). In practice, a good caption refined by regenerating and comparing beats running inversion code.

The right captioner depends on the prompt style the target model expects:

| Target model | Prompt dialect | Best tools |
|---|---|---|
| Flux / FLUX.2, SD3.5, Qwen-Image, Z-Image, gpt-image, Nano Banana | Long natural-language prose | [JoyCaption Beta One](https://huggingface.co/fancyfeast/llama-joycaption-beta-one-hf-llava) (open, uncensored, prompt-style modes), Qwen3-VL via [ComfyUI-QwenVL](https://github.com/1038lab/ComfyUI-QwenVL), or Claude/GPT/Gemini with a "write a prompt for model X" instruction |
| Pony, Illustrious, NoobAI, SD1.5 anime | Danbooru tags plus model quality tokens | [WD EVA02-Large v3 tagger](https://huggingface.co/SmilingWolf/wd-eva02-large-tagger-v3) (tags current to Feb 2024), [Camie Tagger v2](https://huggingface.co/deepghs/camie_tagger_onnx); [ComfyUI-WD14-Tagger](https://github.com/pythongosssss/ComfyUI-WD14-Tagger) |
| Low VRAM, Flux | Prose or mixed caption plus tags | [Florence-2-PromptGen v2.0](https://huggingface.co/MiaoshouAI/Florence-2-large-PromptGen-v2.0) (~1 GB VRAM) via [kijai/ComfyUI-Florence2](https://github.com/kijai/ComfyUI-Florence2) |
| Midjourney | MJ-style prompt plus parameters | `/describe` ([docs](https://docs.midjourney.com/docs/describe)) |

**CLIP Interrogator is legacy.** Its last push was May 2024 and its v0.6 work never shipped ([GitHub](https://github.com/pharmapsychotic/clip-interrogator)). Its "..., trending on artstation" word-bank output suits SD1.5 and mismatches T5- and LLM-encoder models. The many "image to prompt" websites are mostly thin VLM wrappers, and their quality claims come from the vendors themselves ([Taskade](https://www.taskade.com/blog/image-prompt-generators.md)). Taggers have known gaps too: they miss newer characters and tags, and you must add the model's own quality tokens yourself.

## Style transfers best through reference images and LoRAs, not prompt words

Style recovery is more achievable than prompt recovery, because the look can be passed as an image rather than described in words. By late 2026 the strongest zero-shot options are **multi-reference models**. **FLUX.2** accepts up to 10 references and has open [dev] weights ([BFL](https://bfl.ai/blog/flux-2); [GitHub](https://github.com/black-forest-labs/flux2)). **USO** (ByteDance, on Flux.1-dev) separates style from content, takes several style references, and runs natively in ComfyUI ([ComfyUI tutorial](https://docs.comfy.org/tutorials/flux/flux-1-uso)). **Krea 2** offers up to 10 style references with per-reference strength, including negative values, through its app, API or a ComfyUI partner node ([Krea docs](https://www.krea.ai/docs/developers/krea-2/style-transfer)). To restyle a specific content image, use **Qwen-Image-Edit 2509/2511 with QwenStyle** or an sref LoRA ([QwenStyle](https://arxiv.org/html/2601.06202); [TeleStyleV2](https://github.com/Tele-AI/TeleStyleV2)). Edit models alone cannot natively combine a subject reference with a style reference ([TeleStyle](https://arxiv.org/html/2601.20175v1)). On SDXL/SD1.5, IP-Adapter applied only to the style block, the InstantStyle technique, remains the most controllable route. Diffusers exposes it as `set_ip_adapter_scale({"up": {"block_0": [0.0, 1.0, 0.0]}})` ([diffusers docs](https://huggingface.co/docs/diffusers/using-diffusers/ip_adapter)). However, the main ComfyUI pack has been **maintenance-only since April 2025** ([ComfyUI_IPAdapter_plus](https://github.com/cubiq/ComfyUI_IPAdapter_plus)). StyleAligned and RB-Modulation are archived. Nano Banana Pro and GPT Image 2 handle blended references well in vendor demos, but the MultiBanana benchmark found that quality drops as the number of references grows ([arXiv](https://arxiv.org/html/2511.22989v1)). No head-to-head benchmark yet ranks these options on style fidelity.

Inside Midjourney, `--sref` with the image URL plus a tuned `--sw` is the main tool. Sref codes are tied to the `--sv` version, so old codes need `--sv 4` ([Midjourney docs](https://docs.midjourney.com/docs/style-reference)). Moodboards suit sets of three or more images. Ideogram (up to 3 saved style references, 10 on 3.0) and Leonardo (1–4 depending on model) offer similar but smaller features ([Ideogram docs](https://docs.ideogram.ai/using-ideogram/features-and-tools/reference-features/style-reference); [Leonardo help](https://intercom.help/leonardo-ai/en/articles/8497988-image-guidance)).

When you need many images in exactly this style, **train a style LoRA**. ostris/ai-toolkit is the default for Flux.1 and Flux.2 and has an `is_style` mode ([GitHub](https://github.com/ostris/ai-toolkit)). OneTrainer, SimpleTuner, kohya sd-scripts/musubi-tuner and DiffSynth-Studio (for Qwen/Wan) are all active ([OneTrainer](https://github.com/Nerogar/OneTrainer); [sd-scripts](https://github.com/kohya-ss/sd-scripts); [DiffSynth-Studio](https://github.com/modelscope/DiffSynth-Studio)). Community guides put the dataset at **15–50 images**, with gains flattening around 40 ([Apatero](https://apatero.com/blog/flux-lora-dataset-preparation-complete-guide-2025)), and report that higher network rank helps style LoRAs ([Medium](https://medium.com/@calvinherbst/50-flux-2-klein-lora-training-runs-dev-and-klein-to-see-what-config-parameters-actually-matter-3196e4f64fd5)). Captioning advice conflicts. BFL says to caption only content, with no style words ([BFL Klein guide](https://docs.bfl.ai/flux_2/flux2_klein_training_example)), while some trainers repeat the style words in every caption ([Substack](https://estylon.substack.com/p/training-an-ideogram-4-style-lora)). For "exactly this style", content-only captions plus a unique trigger token is the safer default, because the LoRA absorbs the whole look. If you have only one reference image, you have two paths. On SDXL, B-LoRA separates style from content using that single image ([arXiv](https://arxiv.org/html/2403.14572v2)). On any model, you can follow BFL's own documented approach: generate a synthetic set with a zero-shot method, keep the most on-style results, and train on those ([BFL](https://docs.bfl.ai/flux_2/flux2_klein_training_example)).

## Claude needs tools for metadata and generation; no single skill covers the whole job

Anthropic's docs are explicit: **"Claude does not parse or receive any metadata from images passed to it"**. Claude also cannot reliably detect AI images, struggles with images under 200 px, and gives only approximate counts. Claude 4.7+ reads up to a 2,576 px long edge and downscales anything larger, so send crops of fine detail separately ([Claude vision docs](https://platform.claude.com/docs/en/build-with-claude/vision)). Its real strength is structured style description and natural-language prompts. It is weaker than a dedicated tagger at booru tags, and it cannot guess seeds, samplers or LoRAs.

The official anthropics/skills repo has **no image-analysis or reverse-prompting skill**. Its visual skills (canvas-design, algorithmic-art, theme-factory) create art with code ([anthropics/skills](https://github.com/anthropics/skills/tree/main/skills)). The best community option is **[LunarXuan/image-prompt-reverse](https://raw.githubusercontent.com/LunarXuan/image-prompt-reverse/HEAD/README.md)** (~1.1k★, active). It is a SKILL.md skill written for Codex but portable to `~/.claude/skills/`. It enforces an analysis framework (purpose, medium, subject, composition, lighting, color, materials, background, mood) and picks out 3–5 "visual anchors". It treats text inside the image as content rather than instructions, supports roles for multiple references, and has a feedback mode that revises only the parts of the prompt that missed. Its gaps: output is Chinese and English, it targets no specific model, and it has no metadata step. Forcing an analysis step matters in practice, because users report that Claude otherwise jumps straight to writing a prompt without studying the reference ([claudeissues #62128](https://claudeissues.com/issue/62128-claude-fails-to-analyze-user-supplied-reference-images-before-writing-image-gene)).

Two gaps stand out. **No MCP server parses A1111/ComfyUI/NovelAI parameters into structured fields**, and **none computes image similarity** (CLIP, DINOv2, DreamSim). The second is unconfirmed, because search was rate-limited. Both are short scripts that a custom skill can call through Bash.

## The recommended workflow: metadata, then identify, then describe, reference and verify

The table lays out the practical pipeline. Each step runs only if the earlier ones failed to give a definitive answer.

| Step | What to do | Tools | What you get |
|---|---|---|---|
| 0. Get the original | Find the earliest copy: the Civitai post, the file sent as a document rather than a photo, or the creator's upload | Civitai generation data | Untouched metadata, if it exists |
| 1. Dump metadata | `exiftool -j -a -G1 image` | exiftool | Every chunk, EXIF, XMP and JUMBF field |
| 2. Parse a generation recipe | If `parameters`, `prompt` or `workflow` is present, parse it; for ComfyUI, drag the file onto the canvas | SD Prompt Reader CLI / sd-parsers / ComfyUI / comfyui-mcp | **Exact** prompt, seed, sampler and model hash. Look the hash up on Civitai and you are done. |
| 3. Check alpha and provenance | PNG with alpha but no text: try the NovelAI stealth reader. JUMBF present: run c2patool. | `nai_meta.py`, c2patool / c2pa-mcp | Generator, time, edit history (no prompt) |
| 4. Watermark | Suspected Google image: Gemini SynthID check | Gemini app | Yes or no for Google AI only |
| 5. Identify model family | Judge from visual tells, then confirm by regenerating on candidate models; treat detector scores as weak evidence | Judgment, Civitai search, Hive | A best-guess model or LoRA |
| 6. Describe | Run a structured style breakdown (medium, line, rendering, palette hex, lighting, lens, grain, composition, 3–5 anchors) and write the prompt in the target model's dialect | Claude with an adapted image-prompt-reverse skill, JoyCaption, or a WD/Camie tagger for tag models | Prompt with the right meaning (not the original text) |
| 7. Carry the style | Pass the image itself as a style reference | FLUX.2, USO, Krea 2, Qwen-Edit+QwenStyle, IP-Adapter style-only, MJ `--sref` | Close match on the look |
| 8. Verify | Regenerate several seeds; score image-to-image (CLIP image cosine, DINOv2, DreamSim), never image-to-text; revise only what misses; cap the number of rounds | A custom script; a fresh-context critic subagent per [Anthropic's loop guidance](https://claude.com/blog/getting-started-with-loops) | A best-scoring prompt and settings, reported as a range |
| 9. Lock it in | Curate 15–40 on-style outputs and train a style LoRA with content-only captions and a trigger token | ai-toolkit, OneTrainer, kohya | A repeatable style |

For a Claude Code setup, there are two good starting points. If you work locally, install artokun/comfyui-mcp. If you prefer hosted models, add fal or Replicate plus BFL. Then write one SKILL.md that chains steps 1–8, using exiftool and c2patool through Bash, a short Python similarity script, and the image-prompt-reverse analysis rubric. Validated end-to-end benchmarks for this loop do not exist, so the step ordering above is a synthesis of the sources, not a published protocol.

## Conclusion

The practical takeaway is to split two goals that people tend to blur together. Forensic recovery means "what exactly was typed". It is binary and decided before you open any AI tool: either the metadata survived and exiftool gives you the answer, or it didn't and no tool will. Stylistic recovery means "make more like this". It is a matter of degree and keeps getting better, because in 2026 multi-reference models made the reference image itself a better carrier of style than any reconstructed prompt. Effort spent on prompt inversion research beyond a good caption mostly goes to waste. Effort spent on finding the original file, identifying the model family and a regenerate-and-score loop pays off.

The trend also cuts both ways. As commercial generators replace prompt-bearing metadata with C2PA and watermarks, and platforms keep stripping everything, exact recovery will become rarer, limited to images from local tools and community sites like Civitai that keep generation data on purpose. For anyone building tooling, the open gaps are a structured SD-metadata MCP parser and an image-similarity MCP. Each is a short build, and together they would turn Claude from a describer into a closed-loop style matcher.
